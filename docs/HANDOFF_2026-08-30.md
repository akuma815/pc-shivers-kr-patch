- 원본 영문 Windows 1.02의 RESMAP/RESSCI 및 음성·영상 필수 파일 크기/SHA-256을 검사한다. ISO나 읽기 전용 CD를 직접 수정하는 프로그램이 아니다.

- 파일: `extracted/sci/font/02510.fon`
- 크기: 2,120 bytes
- SHA-256: `C39397A93A355546194F4E9188678890B3EE76BBB55E8FEB577A5C15E481E3B2`
- 형식: **SCI 자체 1bpp 비트맵 폰트**
- Windows `.fon` 실행/리소스 형식이 아니다.
- 문자 수: 128
- 명목 line height: 14px
- 전체 글리프 높이: 1–13px
- printable ASCII 글리프: 폭 3–14px, 높이 7–13px
- printable 95자 중 62자는 높이 10px
- 각 글리프는 offset table 뒤에 폭·높이와 행 단위 1bpp 비트맵을 가진다.

따라서 원본 자막의 기준 크기는 14px 줄 높이의 가변폭 비트맵 폰트다.

## 015 독립 음성의 화면 하단 자막 가능성 조사

사용자는 한국어 음성 교체 대신 자막 없는 독립 음성이 재생될 때 영상 자막처럼 화면 하단에 한국어 자막을 표시할 수 있는지 확인해 달라고 했다. 이번 단계에서는 구현·빌드·게임 실행을 하지 않고 정적 구조와 권장 PoC 범위만 확정했다.

### 결론

구현 가능하다. 다만 VMD 영상 옆의 `.srt`를 읽는 ScummVM의 `Video::Subtitles` 경로는 영상 디코더 시간에 묶여 있으므로, `gSounds play:`로 재생되는 SOL 독립 음성에 SRT 파일만 추가하는 것으로는 동작하지 않는다.

게임 자체에는 일반 음성 자막의 선례가 있다. `rm6v240.sc`의 카세트 재생은 자막 플래그 39가 켜졌을 때 `gCurRoom drawText:`로 하단 텍스트를 만들고 `30611~30613` 또는 `30621~30623` 분할 음성을 재생한 뒤 `eraseText:`로 지운다. `ShiversRoom.drawText`는 공용 `DText` 객체를 사용하며 배경색 0, 글꼴 2510, 최대 폭 263으로 화면에 출력한다. 따라서 일반 박물관 방의 음성은 같은 게임 스크립트 패턴으로 자막화할 수 있다.

이름 입력 화면은 예외다. script 922의 `newGame`은 `ShiversRoom`이 아닌 기본 `Room` 인스턴스이며 `35031, 35033, 35034, 35036, 35037, 35038, 35039, 35040` 중 하나를 무작위 재생할 뿐 `drawText`/`eraseText` 메서드를 갖지 않는다. 그러므로 이 화면은 기존 호출 한 줄 추가가 아니라 다음 중 하나가 필요하다.

1. script 922에 전용 `DText` 객체와 표시·정리 코드를 삽입한다.
2. 커스텀 ScummVM에서 디지털 음성 resource ID의 재생·정지를 감시하고 외부 자막 표를 화면 하단에 렌더링한다.

전체 독립 음성으로 확장할 목적에는 두 번째 방법을 우선 권장한다. ScummVM의 `SoundCommandParser::processPlaySound`는 재생 시점에 정확한 `resourceId`를 알고 있으므로, `35036` 같은 ID와 번역·표시 시간을 CSV에서 찾아 자막을 시작할 수 있다. 정지 호출, 자연 재생 종료, 방 전환 때 자막을 즉시 지우는 처리도 함께 넣어야 한다. 현재 `work/scummvm_poc_runner/scummvm_shivers_ko_poc.exe`는 언어 탐지 바이트만 수정한 실행 파일이므로 이 기능에는 ScummVM 소스 기반의 새 PoC 실행 파일이 필요하다.
